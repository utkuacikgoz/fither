## Blockers

**B1 — No hydration gating: cold-start race can wipe a user's entire
progression.** `app/src/state/profile-store.ts:23-40`,
`ledger-store.ts:16-28`, `settings-store.ts:22-35`. zustand `persist`
hydrates asynchronously and nothing waits for it; `startSession` /
`completeSession` read `getState()` directly (`session-store.ts:43,68`).
Cold start with slow/failed storage → session generated against the
initial tier-1 profile and empty history; completion persists that over
her real profile: tiers lost, history truncated; pre-hydration ledger
appends overwritten. Violates "a user who keeps showing up must never
lose a tier" at the app layer. Expected: gate the prompt (or at minimum
start/complete) on all stores hydrated; surface hydration failure.
(S9 folded in: `settings-store.ts:27` regenerates `sessionSalt` on every
launch before hydration overwrites it.)

**B2 — "Show the adaptation" is not implemented on any surface.**
Engine emits `Session.adaptations` correctly (tested); grep for
`adaptation` in `app/` → nothing: no consumer, no strings keys, no
preview line — the prompt routes straight into the player. A quiet/
low-energy/sore user gets a visibly changed session with zero
explanation, against one of the two rules every surface obeys
(fither-domain; ADR-0006).

## Bugs

**G1 — Taste blocks pay the +5 new-tier bonus for a tier never
reached.** `generate.ts:257` flags taste blocks `atNewTier`;
`apply.ts:77-87` pays for any completed `atNewTier` block. Tier-2 user
answers "strong", completes the 1-set tier-3 preview → +5. Contradicts
gamification.md and "taste blocks never count"; makes "strong" gameable.
`generate.test.ts:203` bakes the mislabel in.

**G2 — A fully-empty session flows to "Session complete".** Reachable:
`avoid: [shoulders, hips, core]` empties the entire pool (verified
against the data). 0 blocks → player instantly done → finish shows
"+0 points"; `apply.ts:142-150` appends an empty history entry that
inflates staleness for all five patterns. Expected: zero blocks surfaces
as "couldn't build a session around today's answers"; never enters
history.

**G3 — `saveFailed` is a dead end while the copy promises retry.**
`session-store.ts:67` (`if (finish || saveFailed) return;`) — after one
apply failure no path can retry; the workout is silently lost while
strings.ts:82 says "Try again in a minute."

**G4 — Fallback-tier work counts as "clean sessions at the current
tier".** `generate.ts:175-188` falls down the ladder under constraints;
`apply.ts:57` only excludes blocks above the tier. Sore-ankles tier-3
squat user trains tier-1/2 for three sessions → advanced to tier 4
without tier-3 work. Symmetrically, struggles on easy fallback blocks
feed the higher tier's regression counter. Expected: blocks below
current tier are progression-neutral (like taste blocks above it).

**G5 — Duplicate skill unlocks after regress→re-advance.**
`apply.ts:115-134` emits skillUnlock every time a milestone tier is
entered, no lifetime memory; app doesn't dedupe. Tier 4 → regress →
re-advance → second "Full Push-Up" +25. "Skills are never lost" implies
they can't be re-earned either. Expected: once per (pattern, milestone).

**G6 — `bodyweight-squat` contains "weight"** (name renders in the
player; forbidden list covers data models). Rename scope: exactly three
lines in data/movements.json (id :506, name :507, sit-to-stand
progressionTo :459); zero references elsewhere (grepped). Ids are
pre-release — rename now.

## Smells

- **S1** `fixtures.ts` models impossible engine outputs: tier-2 skill
  unlock (milestones are 4/6); session points for an all-skipped session
  (`session-store.test.ts:63-72` asserts 35 points for skipped×2).
- **S2** `cleanStreak`/`struggledStreak` field names put "streak" in the
  persisted data model — mechanically sanctioned but defeats forbidden-
  list greppability. Rename to `cleanCount`/`struggleCount`.
- **S3** Non-atomic persistence: profile/history and ledger are two
  independent writes; crash between them drops one side. Player state
  unpersisted — crash in the last block discards the workout.
- **S4** Sim struggle model barely bites (median advance week 3 → G2
  near-vacuous). Add a low-capability/slow-gain persona.
- **S5** Rest screen renders no controls though the machine supports
  ending rest early ("rest is hers, never enforced") — locked up to 90s.
- **S6** Every push movement loads shoulders AND wrists; chronic sore
  wrists = zero push forever, unsurfaced. Consider wrist-neutral push
  variants (movement-author, post-Gate-2).
- **S7** `lowEnergy` adaptation fires even when the budget would have
  forced 2 sets anyway.
- **S8** `applySessionResult` signature deviates from the spec's
  Contract line (library param added) — reconcile spec.
- **S9** folded into B1.

## Open-item adjudications

1. `Session.adaptations` → make REQUIRED; fixture carries `[]`.
2. Quiet-never-fires → data-gap-by-design: keep the question and the
   exclusion semantics; v1 library intentionally all-silent; loud
   tier-5/6 variants may come later on merit, never to make a line fire.
3. `bodyweight-squat` → rename to `air-squat` / "Air Squat"; add
   forbidden-language check to the validator (done same day).
4. `STALE_FOCUS_MIN_TRAINING_DAYS = 3` → sound; ratify. Unit is
   sessions, not calendar days — keep naming honest; only `order[0]`
   ever reported (acceptable for a one-line UI).
5. State machine/stores: no double-apply path found (guarded, tested
   idempotent); ledger cannot shrink by API. Real hazards are B1, S3, G3.
