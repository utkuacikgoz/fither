# ADR-0013: Rich visual language and a home hub

- Status: accepted
- Date: 2026-09-03

## Context

The owner tested the full build and called it "functional and boring —
no animations, no images". He is right. Every screen was scored against
the design system's own rules — "calm beats clever", "empty space is a
feature we ship", "one decision per screen" — and passed. The rules were
followed exactly and the result still reads as unfinished rather than
restrained. Austerity is not the same as premium, and the previous
reviews measured the wrong thing: principle compliance rather than
whether the screen feels like a product someone paid for.

The owner also described the flow he expects: sign in → home → exercise
→ back to home → profile / settings / progress. Today the daily prompt
IS the home; there is no hub, and Progress/Settings hang off two small
corner buttons.

## Decision

1. **Calm in colour, generous in craft.** The sage/bone/gold palette and
   the no-guilt voice are unchanged — they are the product. What changes
   is density of care: every screen earns illustration, depth, and
   motion. "Empty space is a feature" is retired as a licence for bare
   screens; whitespace must now be *composed*, not merely left over.
2. **Every movement gets a figure.** A parametric line-figure renderer
   draws each movement's pose from joint data, generated at build time
   into bundled raster assets (no new native dependency, so no rebuild
   is forced on the owner). This is placeholder art with real intent —
   Brief 6's commissioned animation replaces it, and the pose data
   survives that swap as the reference.
3. **Motion is the default, not the exception.** Screen transitions,
   list entrances, number changes, progress fills and the unlock moment
   all move. The old rule allowed exactly one animation in the whole
   product; that rule produced a static app. Reduce Motion is still
   honoured absolutely, and nothing bounces — 250–350ms ease-out.
4. **A home hub, with tabs.** `/` becomes Home: today's card (start or
   continue), current tiers, next skill, recent work. A bottom tab bar
   carries Home / Progress / Settings. The daily prompt becomes a
   pushed flow entered from the home card.
5. **Gate 3 is re-measured, not abandoned.** The hub adds one tap before
   the four questions. Time-to-first-movement instrumentation already
   measures the real number; if it breaches 60s the hub's start action
   gets promoted, not the gate lowered.

## Consequences

- `fither-code/references/design-system.md` is rewritten: the motion
  rule, the whitespace rule and the type rule all change; Norman's six
  stay as they are (they were never the problem).
- The player keeps its sacred-session rule: during work the screen shows
  the movement, the count, the cue and now the figure — still nothing
  else, still no chrome.
- Illustration assets are generated by a script and committed, exactly
  like the brand set, so they regenerate rather than drift.

## Addendum (2026-09-05): the rail token

The phase-3 review found the progress forms' empty segments at 1.2:1
against the card in both themes — a ladder with no rungs — and the
outlined quiet button's hairline at 1.08:1 on the hero wash. A `rail`
token exists now, chosen by arithmetic: with a sage fill this dark on a
white card, no colour is 3:1 from both the page and the fill, so the
rail is set for the state that carries meaning (filled vs empty 3.07:1
light, 3.8:1 dark) and kept visible on the page (1.76:1 / 1.63:1). The
outlined quiet button's hairline is the accent. A tokens contrast test
pins these and the design system's existing AA claims.
