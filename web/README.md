# Recipient page

The static mobile web page a share link lands on. One page, served at `/`
and at `/s/<scenario>`; the scenario is read from the path and nothing
else. Wave 3 of docs/implementation-checklist.md; copy from
docs/growth/treatments.md and docs/growth/pilot-brief.md; visual language
from docs/design/mockups/recipient-page.html.

## Layout

| path | what |
|---|---|
| `index.html`, `s/index.html` | the page, pre-rendered generic; identical files, generated by `scripts/build-page.mjs` |
| `src/content.mjs` | copy per scenario; the allowlist is its keys |
| `src/render.mjs` | pure rendering, no DOM; shared by the browser and the tests |
| `src/app.js` | browser entry; `APP_STORE_URL` and `COLLECTOR_URL` at the top are the owner's |
| `src/page.css` | styles, tokens mirrored from `docs/design/mockups/tokens.css` |
| `assets/` | self-hosted Manrope, pre-tinted movement figures, the mark (`scripts/build-assets.py`) |
| `.well-known/apple-app-site-association` | universal links template |
| `test/page.test.mjs` | `pnpm web:test` |
| `preview/*.png` | one render per scenario plus `generic.png` (`scripts/preview.py`) |

Scenarios: `friends_week`, `between_meetings`, `away_from_home`,
`quiet_house`, `session`, `week`. Anything else, including a missing or
malformed segment, renders the generic page; the input never reaches the
DOM. Query strings and fragments are never read.

## Commands

```
pnpm web:test                        # node --test web/test/*.test.mjs (Node 22 rejects a bare directory)
node web/scripts/build-page.mjs      # regenerate index.html and s/index.html after editing src/
python3 web/scripts/preview.py       # previews via a local server and the pinned Chromium
python3 web/scripts/build-assets.py  # refresh fonts and figures from app/assets
```

## Deploying: the live site is the fither-web repository

`fither.app` is served by Vercel from the sibling `fither-web` repository
(landing page, privacy, terms). This directory stays the source of the
recipient page; after editing `src/` run

```
node web/scripts/build-page.mjs && node web/scripts/sync-site.mjs ../fither-web
```

and commit the result in `fither-web`. The sync writes `s/` (the page, its
CSS and modules, with `/src/` paths rewritten to `/s/`), the figures, and
`.well-known/apple-app-site-association`; `fither-web/vercel.json` rewrites
`/s/<scenario>` to the page and serves the association file as JSON with
no trailing-slash redirect.

## Deploying on another static host

Any static host works (Cloudflare Pages, Netlify, Vercel static, S3 with
a CDN, nginx). Publish the `web/` directory as the site root and set up
three things:

1. **Rewrite `/s/*` to `/s/index.html`** with status 200, not a redirect.
   The path must survive as typed; the page reads it. Examples:
   - Netlify `_redirects`: `/s/*  /s/index.html  200`
   - Cloudflare Pages `_redirects`: same line
   - nginx: `location /s/ { try_files /s/index.html =404; }`
   - Vercel `vercel.json`: `{ "rewrites": [{ "source": "/s/:id", "destination": "/s/index.html" }] }`
2. **Serve `/.well-known/apple-app-site-association`** at the root of the
   domain over HTTPS, with `Content-Type: application/json`, no redirect,
   no `.json` extension, no authentication. Apple's CDN fetches it once
   per install and on update, so a wrong content type fails silently.
   Replace `REPLACE_WITH_TEAM_ID` in the file with the Apple Team ID from
   App Store Connect before deploying; the test keeps the placeholder
   marked until then.
3. **Root-absolute assets.** The page references `/src/…` and
   `/assets/…`; it must be served from the domain root, not a subpath.

The page sets a Content Security Policy that allows only its own origin.
No cookies are set, no third-party script is loaded, no font or image
comes from another host.

## App side, when a domain exists

Add the associated domain to `app/app.json` (ui-engineer change, not made
here):

```json
"ios": {
  "associatedDomains": ["applinks:<domain>"]
}
```

The app's `deep-link.ts` already keeps the path only and drops the query
unread; `scenario_entry` takes the allowlisted id from `/s/<id>`
(ADR-0024 §3). The allowlist in `app/src/analytics/events.ts` must match
the keys of `src/content.mjs`.

## The install boundary

Universal links open the installed app directly from the link, with the
path intact. When the app is not installed, the link opens this page and
the button goes to the App Store. Nothing crosses the store: iOS offers
no deferred deep link, the app is never told which page she came from,
and the page never tries to pass anything through (no clipboard, no
token, no fingerprint). After install the app runs the ordinary first-use
flow and asks her to pick the scenario herself if she wants it; the
recipient page never promises otherwise.

The button's only destination is `APP_STORE_URL` in `src/app.js`. While
it is empty the page shows "Coming to the App Store." and no button;
there is no placeholder link. Only an `https://apps.apple.com/` URL is
accepted; anything else is treated as unset. `pnpm web:test` checks the
constant.

## Analytics

Same minimisation as the app (docs/measurement.md, ADR-0024 §4): one
page-view beacon per view, carrying the canonical path and the scenario
id only (`{"path":"/s/quiet_house","scenario":"quiet_house"}`, or `/` and
`null` for the generic page). No cookies, no identifiers, no query
string, no referrer (`no-referrer`), no user agent beyond what the
browser sends on its own. The beacon is off until `COLLECTOR_URL` in
`src/app.js` names a collector; when it is set, add the collector's
origin to `connect-src` in `src/render.mjs` and rebuild, or the CSP
blocks the request. Recipient numbers cannot be joined to the sender or
to a later install; the pilot brief and measurement doc say so.

## What is external

- **Domain**: none yet. Until it exists nothing here is `live`; the
  association file and the app entitlement both wait on it.
- **App Store listing**: `APP_STORE_URL` stays empty until the listing
  URL exists.
- **Collector**: `COLLECTOR_URL` stays empty until one exists; PostHog
  or a static-host analytics endpoint would do, subject to the same
  minimisation.
- **Link previews**: Messages renders a preview from the page's HTML.
  Per-scenario preview text needs per-path HTML or a host-side function;
  the single page carries the brand title only.
- **`week` copy**: no brief names it; `src/content.mjs` carries a first
  draft for the copy-writer.
